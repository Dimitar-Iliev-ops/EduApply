# Начална микросървисна структура

EduApply запазва съществуващото MVC приложение с Identity, SQL Server и миграциите му. Новият React интерфейс и трите .NET 8 услуги се стартират отделно и могат да се разглеждат без SQL Server. Демото показва само публични примерни данни.

| Част | Отговорност | Какво работи сега |
| --- | --- | --- |
| `frontend/` | React + TypeScript потребителски интерфейс | Каталог на кампаниите, състояние на услугите, начални секции за заявления и класиране |
| `EduApply.Catalog.Api` | Публични кампании и паралелки | Четене на една примерна кампания от паметта |
| `EduApply.Applications.Api` | Заявления, желания и документи | Самостоятелно стартиране и проверка на състоянието |
| `EduApply.Ranking.Api` | Изчисляване на бал и резултати | Самостоятелно стартиране и проверка на състоянието |

Услугите нямат зависимости една от друга и не четат от общата база. При разработка Vite препраща заявките `/api/catalog`, `/api/applications` и `/api/ranking` към съответната локална услуга. Проверките на състоянието удостоверяват, че процесите отговарят; те не означават, че приемът работи.

## Стартиране

Изискват се .NET 8 SDK (виж `global.json`) и Node.js 22.12+ или 24. Изпълнете от основната папка:

```powershell
dotnet build EduApply.sln
npm --prefix frontend ci
```

След това стартирайте всяка команда в отделен терминал:

```powershell
dotnet run --project src/Microservices/EduApply.Catalog.Api --launch-profile local
dotnet run --project src/Microservices/EduApply.Applications.Api --launch-profile local
dotnet run --project src/Microservices/EduApply.Ranking.Api --launch-profile local
npm --prefix frontend run dev
```

Отворете [React демото](http://127.0.0.1:5173/). Ако спрете каталога, страницата показва съобщение и бутон за повторен опит. Останалите API услуги отговарят независимо. В [API примерите](../src/Microservices/starter.http) има заявки за директна проверка.

За проверка на TypeScript и създаване на пакет изпълнете `npm --prefix frontend run build`. Локалното препращане на API заявките е настройка на Vite за разработка. За публикуване на пакета е нужно отделно маршрутизиране на същите API пътища.

## Какво предстои

1. Проектиране на собствено съхранение за каталога. Демо записът в момента не е синхронизиран с SQL Server.
2. Свързване на вход и роли преди добавяне на заявки за създаване или промяна на заявления. Сегашното MVC приложение продължава да отговаря за Identity.
3. Уточняване на договора за одобрени заявления и правилата за бал, капацитет и равни резултати, преди да се изгради класирането.
